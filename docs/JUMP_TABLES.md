## 1. Current layout facts (verified)

### 1.1 Two different homes for `jtbl_*`

| where | file | jump tables | notes |
|---|---|---|---|
| main `text` segment | `asm/us/data/A23F0.rodata.s` (subsegment `- [0xA23F0, rodata]`, rom `0xA23F0..0xA6860`) | 153 | already a real `.rodata` blob |
| main `text` segment | `asm/us/data/A6FD0.rodata.s`, `A8600.rodata.s` | 0 | post-libultra rodata / F3DEX bin |
| 67 overlay fragments | `asm/us/data/fragments/NN/fragmentNN_data.data.s` (subsegment `- [.., data, ..]`) | 628 | typed `data`, i.e. linked into the `.data` output section |

656 `GLOBAL_ASM` owners reference a `jtbl_*`: **151 in the main `text` segment,
505 inside fragments.** Collapsed into contiguous single-owner runs that is
**182 runs** (34 in `text`, 148 in fragments) — see `docs/jump-tables/plan.txt`.

### 1.2 The linker script already has the right shape

`linker_scripts/us/pokestadiumgs.ld` (generated by splat) emits, per code
segment:

```
.fragment67 0x82900000 : AT(fragment67_ROM_START) SUBALIGN(16)
{
    fragment67_TEXT_START = .;      ... .o(.text) ...
    fragment67_DATA_START = .;      ... .o(.data) ...   <- fragmentNN_data.data.o lands here
    fragment67_RODATA_START = .;    ... .o(.rodata) ... <- all empty today
}
```

So each object *already* has a `.rodata` slot; it is simply empty because splat
was never told which bytes belong to it. `.data` and `.rodata` are adjacent in
the output with no gap other than `SUBALIGN(16)` padding — **moving the
data/rodata boundary is byte-neutral as long as the boundary is 16-byte
aligned.** That is the whole trick, and it is why fragments do not require
knowing the true original `.data`/`.rodata` split.

### 1.3 Ownership is derivable and monotonic

I mapped every symbol in `A23F0.rodata.s` to the C file whose functions
reference it (scan of `asm/us/nonmatchings/**` + `src/**.c`). The result is a
clean partition into 50 contiguous runs, **in exactly the same order as the C
files appear in the `text` segment**, with only 4 short runs of unreferenced
symbols whose owner is ambiguous. Every `jtbl_*` run has exactly **one** owner
(0 ambiguous jump-table runs across the whole ROM).

That confirms: the ROM's rodata for a segment *is* laid out per object in link
order, so a per-object `.rodata` subsegment can reproduce the exact byte order.

### 1.4 Fragment structure (bonus, verified by parsing the ROM)

The 0x20-byte `fragmentNN_header` is
`{ j <entry>; nop; "FRAGMENT"; textStart=0x20; relocTableOff; loadedSize; memSize }`.
`relocTableOff` is the end of the loaded image (= end of rodata) and the start of
a Zelda-style relocation table (`count`, then packed `type|offset` words).
Checked against fragment 2 / 67 / 69: `loadedSize` matches the yaml segment span
exactly, and `relocTableOff` for fragment 69 (`0x40A0`) lands exactly on
`D_8F1040A0`, the first word of the reloc table. Useful if you ever want the true
`.data`/`.rodata` split — but, per §1.2, you do not need it.

## 2. The change pattern

### 2.1 yaml

Split the shared blob into `before / owner / after`:

```yaml
    # .rodata
    - [0xA23F0, rodata]
    - [0xA6070, .rodata, 667B0] # jtbl_800A5470 (func_80065BB0)
    - [0xA6090, rodata]
```

* The **dotted** type `.rodata` is what pairs the subsegment with the `c`
  subsegment of the same name (`- [0x667B0, c]` → name `667B0`). splat then
  * does **not** emit a standalone `.s` for it (`CommonSegData.split` returns
    early for dotted types),
  * migrates the symbols into `asm/us/nonmatchings/667B0/func_80065BB0.s` as a
    `.section .late_rodata` block that asm-processor folds back into the object,
  * emits the linker entry as `build/src/667B0.o(.rodata)` **at that yaml
    position** instead of in the auto-generated block.
* The trailing subsegment **must** be typed `rodata` (not `data`), otherwise it
  would be linked into the `.data` output section, i.e. *before* the rodata.
* Both offsets must be 16-byte aligned (`SUBALIGN(16)`). Widen outwards if the
  natural run is not: the extra bytes are simply attributed to the neighbouring
  object, which is still byte-identical because the blocks stay adjacent.

### 2.2 linker script (generated — do not hand-edit, but do re-apply the aliases)

Re-running splat rewrote `pokestadiumgs.ld` with exactly two line moves:

```diff
         build/src/65E20.o(.rodata);
+        build/asm/us/data/A23F0.rodata.o(.rodata);
         build/src/667B0.o(.rodata);
...
         build/src/74020.o(.rodata);
-        build/asm/us/data/A23F0.rodata.o(.rodata);
+        build/asm/us/data/A6090.rodata.o(.rodata);
```

**Gotcha:** splat also *deletes* the hand-written descriptive-alias block
(`Audio_InitializeTaskState = func_80021B00;` …, 11 lines) that lives inside
`.text`. It must be re-inserted after every split. Longer term it belongs in a
separate `.ld` include so splat cannot clobber it.

### 2.3 C body

Delete the `#pragma GLOBAL_ASM` and write the `switch`. IDO emits the table into
the object's `.rodata` automatically; nothing else is needed.

## 4. End-to-end prototype

**Target:** `src/667B0.c` / `func_80065BB0` (`0x667B0..0x66990`, 0x1E0 bytes,
the *only* function in the file), rodata run `0xA6070..0xA6090` = exactly
`jtbl_800A5470` (7 cases + one padding word), both ends already 16-aligned.

### Step A — subsegment only, assembly owner kept

yaml change from §2.1 → `splat split` → re-apply aliases → `make COMPARE=1`.

* `asm/us/nonmatchings/667B0/func_80065BB0.s` now begins with
  `.section .late_rodata / dlabel jtbl_800A5470 / …` followed by `.section .text`.
* `build/src/667B0.o` gained `.rodata  00000020  … 2**4`.
* **ROM matched.** ✅

### Step B — real C `switch`

`tools/pragma_targets.py draft func_80065BB0` returned an empty m2c draft
(`/* error: */`), so the body was written by hand. Final `src/667B0.c` is in
`docs/jump-tables/jump-table.patch`. Verification of the compiled object against the
step-A object:

```
.text   IDENTICAL   (0x1E0 bytes)
.rodata IDENTICAL   (0x20 bytes, align 2**4)
```

Relocations differ only cosmetically: IDO emits section-relative
`R_MIPS_HI16/.rodata` + `R_MIPS_32/.text` where the assembler emitted
`R_MIPS_HI16 jtbl_800A5470` + unnamed `R_MIPS_32`; and the HI16/LO16 pairs for
`fragment12_ROM_START` / `D_8009DEB0` are emitted in a different order. Both are
link-equivalent.

**Full clean rebuild: `build/pokestadiumgs-us.z64: OK`.** ✅

### Step C — the same pattern inside a fragment (`data`-typed blob)

Fragment 69 has a single C file (`fragment69_code`) and three tables at
`0x8F104014 / 0x8F10404C / 0x8F10407C`. The 3-way split:

```yaml
    - [0x358830, textbin, fragments/69/fragment69_header]
    - [0x358850, c,       fragments/69/fragment69_code]
    - [0x35C130, data,    fragments/69/fragment69_data]
+   - [0x35C840, .rodata, fragments/69/fragment69_code] # jtbl_8F104014/404C/407C
+   - [0x35C8D0, rodata,  fragments/69/fragment69_reloc]
```

`0x35C840` is the first 16-aligned address at or below the first table
(`0x35C844`); `0x35C8D0` is where the fragment's relocation table starts (from
the header's `relocTableOff` field, §1.4) and is already 16-aligned.

splat produced `asm/us/data/fragments/69/fragment69_reloc.rodata.s`, migrated the
three tables plus the interleaved floats into the `nonmatchings` bodies, and the
linker script came out as

```
        fragment69_RODATA_START = .;
        build/asm/us/data/fragments/69/fragment69_header.o(.rodata);
        build/src/fragments/69/fragment69_code.o(.rodata);
+       build/asm/us/data/fragments/69/fragment69_reloc.rodata.o(.rodata);
```

`fragment69_code.o` gained `.rodata  00000090  … 2**4`, and the
**ROM still matched**. ✅  So the fragment case is verified too — no C body was
written for it, but the section plumbing (the part that was blocked) works.

Two IDO-faithfulness findings worth recording, because both cost iterations:

1. **A 2-case dispatch must be written as a nested `switch`, not `if/else`.**
   `if (x==0) … else if (x==0x300) …` produced `bnez`-first inverted branches;
   `switch (x) { case 0: … case 0x300: … default: … }` produced the ROM's
   `beqz` / `beq` / `b` compare chain with `nop` delay slots.
2. **Stack-local declaration order changes the frame layout.** With
   `Unk667B0 sp30; s32 ret; s32 i;` the aggregate landed at `sp+0x38`
   (frame 0x68); moving the scalars first — `s32 ret; s32 i; Unk667B0 sp30;` —
   moved it to `sp+0x30`, and shrinking the aggregate to 0x28 gave frame 0x60,
   matching. IDO lays out locals as `[outgoing args][saved regs][scalars][aggregates]`.
3. The source's `case` bodies are emitted in **source order**, which here is
   `1,2,3,5,4,7,default` — recoverable by reading the memory order of the case
   bodies rather than the jump-table order.

## 5. Generalisation plan

### 5.1 What the ROM gate needs, in one sentence

For each file that owns jump tables, add one `.rodata` subsegment covering a
16-byte-aligned window around that file's rodata run, plus a `rodata`-typed tail
subsegment for whatever follows — declared in ascending ROM order.

### 5.2 Working script

`docs/jump-tables/add_rodata_subsegments.py` (tested read-only against the main
checkout; ~1 s for the whole ROM). Two commands:

* `plan` — enumerates all 182 jump-table runs with their derived
  `rom_start..rom_end`, owner file, and risk flags. Output saved as
  `docs/jump-tables/plan.txt`.
* `for-jtbl <sym>` — prints the exact yaml lines for one table. It reproduces the
  prototype's `- [0xA6070, .rodata, 667B0]` / `- [0xA6090, rodata]` byte-for-byte
  from the *unmodified* main checkout, which is the script's regression test.

How it derives things:

1. Parse `yamls/us/rom.yaml` into segments (`start`, `vram`, subsegment list).
2. For every `rodata`/`data` subsegment, parse the generated `.s` for
   `(vram, rom, symbol)` in file order.
3. Build a symbol→owner index by scanning `asm/us/nonmatchings/**/*.s` (the
   directory name is the owning C file) and `src/**.c`.
4. Collapse into contiguous single-owner runs; a jump-table run's window is
   `[run_start & ~15, (run_end + 15) & ~15]`.
5. Emit the owner line plus the tail `rodata` line.

If it were promoted into the repo it should live at
`tools/add_rodata_subsegments.py` and gain a `--apply` mode that rewrites the
yaml in place. I deliberately did not add it to the main checkout.

### 5.3 Recommended rollout order

1. **Main `text` segment first — 34 runs, essentially free.** The blob is
   already `.rodata`; only 2 of the 34 runs are unaligned (both belong to
   `229E0`, and both widen safely because the neighbours are also `229E0` or
   unreferenced). This unblocks 151 of the 656 owners.
2. **Fragments — 148 runs, one fragment at a time.** All 148 sit inside a `data`
   subsegment, so each needs the 3-way split (`data` head / `.rodata` owner /
   `rodata` tail). 61 of them are unaligned and need widening.
3. Do it lazily: only add the subsegment for a file at the moment you decompile
   one of its dispatchers, so a mistake is caught by that file's own gate run
   rather than by a wholesale re-split.

For the MCP runner: once a file has its `.rodata` subsegment, its dispatchers
stop being `section_layout_drift` cases and become ordinary text-match probes,
so `_compare_link_shape` should no longer reject them. The runner's isolated
probe must compare `.rodata` as well as `.text` for those objects.

### 5.4 Risks, ranked

| risk | how it shows up | mitigation |
|---|---|---|
| **Non-migratable rodata gets silently dropped.** splat migrates a rodata symbol into a function's `.s` only if exactly one function references it. Anything else goes through `create_unmigrated_rodata_file`, which is skipped when the C file already exists and has no matching pragma → those bytes vanish from the build. | ROM size/layout drift right after the split | after each split, check that the `.rodata` size of the owner object equals the subsegment size (`mips-linux-gnu-objdump -h build/src/X.o`); or temporarily delete the C file so splat regenerates it with all pragmas, then merge. `plan` already flags ambiguous-owner runs (currently 0 for jump tables, but non-jtbl symbols inside a widened window can still hit this). |
| **`.rodata` vs `.late_rodata` ordering.** spimdisasm classified `jtbl_800A5470` as `.late_rodata`; IDO put the C `switch`'s table in plain `.rodata`. It matched here because the object had exactly one rodata symbol. A file with strings *and* floats *and* jump tables can reorder. | `.rodata` bytes differ while `.text` matches | diff the object's `.rodata` against the step-A (assembly-owner) object before touching the C body — that isolates ordering from codegen. |
| **Fragments interleave rodata with `.data` that carries relocations.** e.g. fragment 67 has `.word D_829172CC` pointers immediately before the first jump table. | pulling too much into `.rodata` moves relocatable pointers into a read-only section | keep the `.rodata` window as tight as alignment allows; never widen past a symbol whose contents are `.word D_…`/`.word func_…`. |
| **Alignment.** 61 fragment runs are not 16-aligned; `SUBALIGN(16)` would insert padding at a bad boundary. | ROM shifts by 4/8/12 bytes | always widen to 16, and re-check that the widened window does not swallow a symbol owned by a *later* file (order must stay monotonic). |
| **splat clobbers the alias block in the `.ld`.** 11 hand-written `X = func_Y;` lines are deleted on every split. | link failure or silently lost aliases | move them to a separate included `.ld`, or re-apply after every split (a 5-line script). |
| **splat version drift.** see §3. | 7,700 asm files change; asm-processor errors | pin spimdisasm to the `requirements.txt` commit; the current `disasm/.venv` is a *broken Linux container venv* (`#!/work/.venv/bin/python3`, `python3 -> /usr/bin/python3`) and has no splat installed at all. |
| **Stale `asm/` files.** the main checkout has 4,203 `.s` files a fresh split no longer emits (renamed symbols). | none today; the build ignores them | be aware that `rm -rf asm/us && splat split` is safe (verified: ROM still matched) but removes them. |

## 6. What was verified vs. assumed

**Verified by building and comparing the ROM:**
* fresh splat split with the pinned spimdisasm reproduces the matching ROM;
* the `.rodata` subsegment for `667B0` keeps the assembly-owner ROM matching;
* the C `switch` version of `func_80065BB0` produces byte-identical `.text` and
  `.rodata` and a matching full ROM (clean rebuild from an empty `build/`);
* the linker script places `build/src/667B0.o(.rodata)` between
  `A23F0.rodata.o` and `A6090.rodata.o`, i.e. at the correct ROM position;
* the same 3-way split inside fragment 69 (`data` head / `.rodata` owner /
  `rodata` tail) — correct linker ordering, 0x90-byte `.rodata` on the owner
  object, ROM still matching;
* the fragment header field layout, by parsing three fragments out of the ROM;
* the ownership map for the main `text` rodata blob (50 contiguous runs, no
  ambiguity among jump tables);
* `add_rodata_subsegments.py for-jtbl jtbl_800A5470` reproduces the
  hand-derived offsets from the unmodified checkout.

**Assumed / not yet tested:**
* that a C `switch` inside a **fragment** matches. The section plumbing is
  verified (Step C: fragment 69 split, `fragment69_code.o(.rodata)` = 0x90 bytes,
  ROM matched), but no fragment function was actually decompiled, so the
  interaction between an IDO-emitted table and a fragment's *relocation table*
  (which is static ROM data and therefore unchanged) is reasoned, not measured.
* that widening an unaligned run is always safe. It is safe whenever the
  swallowed bytes belong to the *same or an earlier* object; the script does not
  yet prove that, it only flags the case.
* the `.rodata`/`.late_rodata` interaction for files with mixed rodata.
* the exact meaning of the fragment reloc-table section bits (parsed, but the
  top-2-bit field does not map cleanly to text/data/rodata, so the true
  `.data`/`.rodata` split inside a fragment is still unknown — and, per §1.2,
  still not needed).
