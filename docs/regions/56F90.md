# Transfer Pak I/O — accepted SDK-object batch, 2026-10-20

Three assembly owners are replaced by ordinary C:

- `GbPak_SelectRamBank` (`func_800564BC`, 160 bytes) fills the actual
  32-byte command buffer and writes it to GB address `0x4000`. It updates
  `D_8012855C[port]` only after a successful write. `func_8005655C` compares
  that cache with its 8-KiB RAM-window bank before reading/writing at `0xA000`.
- `GbPak_InitializeCartridge` (`func_80056F7C`, 188 bytes) clears the port
  state, initializes the SDK handle, reads the cartridge ID, checks the
  `OS_GBPAK_RSTB_STATUS` bit and connector, then performs `func_80056390`
  and marks the state one. It returns whether the state is one.
- `GbPak_ReadIdAndDetectRam` (`func_80056870`, 240 bytes) optionally copies
  the old state, returns early for state one, otherwise reads the ID and
  checks the connector before calling `func_80056390` and `GbPak_DetectRam`.
  It marks the port checked even when detection returns zero, preserving
  the original control flow and shutdown call on an ID-read error.

The `OSPfs`, `OSGbpakId` and `OSMesgQueue` objects and SDK call contracts
come from the vendored libultra headers. The existing byte-spelled global
handle base is converted to `OSPfs *` before array indexing; the target
handle stride is 104 bytes. No substitute layout or dummy storage is added.

The bank writer's source loop is naturally unrolled by IDO; its real result,
handle and counter locals precede the real 32-byte buffer. Initialization
keeps the meaningful state pointer while repeating the constant handle
expression. ID/RAM detection repeats both actual address expressions instead
of keeping extra pointer locals. These spellings reproduce the original
frames and cache homes without manual unrolling or artificial frame fillers.

preserves the complete accepted object and twenty-leading-blank control.
After its normal ROM gate, the still-unaccepted body is retried as a known

## Clock I/O pair, 2026-10-20

`GbPak_ReadClock` (`func_800574E0`, 352 bytes) enables cartridge RAM,
runs `func_80057318`, then reads register selectors 8, 9, 10, 12 and 11
through `func_800573C4`. It masks the seconds, minutes and hours to six
bits, combines the two day bytes and preserves the original `% 140`
conversion and both halfword stores. The read path's six-bit hour mask
is preserved even though the write path uses five bits.

`GbPak_WriteClock` (`func_80057640`, 292 bytes) writes seconds, minutes,
hours, the low day byte and the high day bit through `func_80057450`.
Every SDK error returns immediately. Both owners invalidate the cached
RAM bank only after the complete successful sequence. Their save-layer
consumers are `func_8005F190` and `func_8005F3E0`.

The reader's actual low/high byte locals precede its error result. The
writer keeps the promoted day value for the two byte writes and selects
the low byte explicitly with `& 0xFF`. All locals carry real values; there
is no dummy storage, forced register, manual unrolling or output rewrite.

The callers test `func_800572D8`'s SDK result, so its definition now returns
`s32`. Its old 40-byte array with an eight-byte unused prefix is replaced
by the actual 32-byte transfer buffer and a returned error local. Complete

its entry mask and the SDK transfer interface. Both accepted clock bodies

## RAM-access bootstrap, 2026-10-20

`GbPak_EnableRamAccess` (`func_80056390`, 300 bytes) first checks the SDK
status, fills the actual 32-byte transfer buffer with ones and writes it
to `0x6000`. It then zeroes the same buffer, sets its last byte to 10 and
writes it to `0x0000`. Successful writes invalidate the cached RAM bank.
The final status query requires `OS_GBPAK_POWER`; SDK errors are returned
immediately and a missing power bit returns `PFS_ERR_CONTRFAIL`.

The checked SDK result is reused as the first fill's `for` counter; a
separate `s32` index drives the second fill's `do` loop. Every local
carries a real value. IDO naturally unrolls the zero fill four bytes at a
time. The SDK handle address is derived independently at each call, as an
`OSPfs` array access, so the optimizer owns its cache rather than a second
source pointer local. This gives the original 88-byte frame, handle home
40, buffer home 44 and status home 79 without forcing offsets or registers.

The prior four-instruction residual was isolated with ten fresh
current-known/exact-parent stock-capture controls. Its frontend stream
reserved 48 local bytes; the optimizer created a separate handle cache
at displacement -52 even though the source pointer occupied -8. Removing
the source pointer local, while retaining both meaningful fill counters,
closes that residual. Narrow-counter and countdown-loop experiments do
not reproduce the original loop; none of those candidates is installed.

The owner has accepted runner provenance and a normal full-ROM gate.
Naming and declaration cleanup pass whole-game-object and twenty-leading-
blank controls. The one old-name relocation from the still-assembly scanner
is covered by the explicit compatibility alias. Independent retail-address
links match all 31 original extents and 5,696 text bytes for the original,
first acceptance and named snapshots, as well as canonical/descriptive
names, native/public compiler paths and their blank controls. Both gates
freeze all five complete main/support units and check every receipt/hash
inside the successful callback and before further compilation. Final ROM
MD5 remains `1561c75d11cedf356a8ddb1a4a5f9d5d`; the all-source host syntax
check and all 76 native tests pass. No experiment driver, output rewrite,
padding, dummy storage or coverage edit is part of the change.

## Four-port initialization, 2026-10-20

`GbPak_InitializePorts` (`func_80056C98`, 504 bytes) clears the port masks,
queries plugged Paks and walks all four controller ports. Unplugged ports,
the fourth-port exclusion hook and failed `osGbpakInit` calls skip to the
next port. Each successful SDK initialization sets `D_80128554`'s bit and
reads a real `OSGbpakId` plus status byte. The original reset-status check,
title check, connector check and shutdown reason 2 are preserved. Successful
or unchecked-title ports get state one and their `D_80128555` bit; ID-read
failures clear the state, with `PFS_ERR_CONTRFAIL` taking the shutdown path.
The return value packs `D_80128555` above `D_80128554` in bits 16 and 0.

Early plug/init phase guards reproduce the original loop's register
priorities. The successful connector phase has its own meaningful state
pointer, used after `GbPak_EnableRamAccess`. The default-title phase updates
the mask then state; IDO schedules the independent stores to their original
instruction order. Deriving SDK handles directly at their three calls avoids
an extra source pointer home and reproduces the 168-byte frame. All locals
are actual SDK objects, loop/error values or used pointers. No output or
instruction rewrite, artificial object or manual padding is involved.

Both initialization owners have separate normal runner/full-ROM acceptance
receipts. Their final named gate freezes and externally hashes all five
complete units inside the successful callback and again before compilation.
Independent retail-address links cover all 31 original extents and 5,696
text bytes for the original, both acceptance stages and both naming stages.
Canonical/descriptive names, native/public compiler paths, twenty-leading-
blank controls and accepted-attempt provenance pass. The final normal ROM
gate retains MD5 `1561c75d11cedf356a8ddb1a4a5f9d5d`; all-source host syntax
and all 76 native regression tests pass. Old names retain explicit aliases.
