### DV extraction and stat arithmetic

The DV switch selects HP at index 0, attack/defense/speed at 1/2/3, and
the shared special nibble at 4/5/6. HP combines the low bit of each packed
nibble. The base-stat lookup `func_80063838`, the six stat destinations in
`func_800619E8`, and the observed packed-DV offset 0x16 establish the names.
Out-of-range indices leave the DV result uninitialized, as in the original.

`Pokemon_CalculateStat` obtains the species base stat and DV, adds one
quarter of `StatExpSqrt(stat_exp)`, scales by level/100, then adds level+10
for HP or 5 otherwise. The unsigned halfword result wraps before the cap
at 999. Preserve that ordering; widening the result changes exceptional
input behavior. Staging the HP addition and using an unsigned word return
reproduce the original cap tail. Signed halfword/word return alternatives
leave sign-extension or branch/carrier differences. The existing 144-byte
per-file rodata, including jump tables, is unchanged.

The DV owner initially matches through relocation masking and a sequential
full-ROM gate; it is not directly link-verified. The other three owners
pass direct object link verification followed by full-ROM gates.

and packed DVs after its two word-sized selector arguments. Its earlier

the level owner is installed.

### Inverse searches

`Pokemon_StatExpForTarget` tests odd stat-experience values starting at 3,
stopping when the calculated stat exceeds the requested value, and returns
the preceding odd value. It retains the original signed comparison through
an `s32` call-result local. Removing that local compares unsigned instead.
The final loop value is 0xFFFF if no earlier threshold is found.

`Pokemon_LevelFromExp` tests the next level's experience requirement using
`func_80061B88`; the original unsigned experience comparison and loop
bounds produce levels 2..100. The existing six-stat recalculation consumer
stores that result in its level field at 0x1D. Preserve the lower bound
of 2 rather than substituting another game's level-search policy.
