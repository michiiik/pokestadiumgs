### DV extraction and stat arithmetic

The DV switch selects HP at index 0, attack/defense/speed at 1/2/3, and
the shared special nibble at 4/5/6. HP combines the low bit of each packed
nibble. The base-stat lookup `func_80063838`, the six stat destinations in
`func_800619E8`, and the observed packed-DV offset 0x16 establish the names.
Out-of-range indices leave the DV result uninitialized, as in the original.

`Pokemon_CalculateStat` obtains the species base stat and DV, adds one
quarter of `StatExpSqrt(stat_exp)`, scales by level/100, then adds level+10
for HP or 5 otherwise. The unsigned halfword result wraps before the cap
at 999. Preserve that ordering; widening the result changes exceptional
input behavior. Staging the HP addition and using an unsigned word return
reproduce the original cap tail. Signed halfword/word return alternatives
leave sign-extension or branch/carrier differences. The existing 144-byte
per-file rodata, including jump tables, is unchanged.

The DV owner initially matches through relocation masking and a sequential
full-ROM gate; it is not directly link-verified. The other three owners
pass direct object link verification followed by full-ROM gates.

### Inverse searches

`Pokemon_StatExpForTarget` tests odd stat-experience values starting at 3,
stopping when the calculated stat exceeds the requested value, and returns
the preceding odd value. It retains the original signed comparison through
an `s32` call-result local. Removing that local compares unsigned instead.
The final loop value is 0xFFFF if no earlier threshold is found.

`Pokemon_LevelFromExp` tests the next level's experience requirement using
`func_80061B88`; the original unsigned experience comparison and loop
bounds produce levels 2..100. The existing six-stat recalculation consumer
stores that result in its level field at 0x1D. Preserve the lower bound
of 2 rather than substituting another game's level-search policy.

### Mode-specific character conversion

The decoder maps one byte through the selected character table. Mode 1
uses `D_80097380`, modes 2/3 use `D_80097480`, modes 4/5 use `D_80097580`,
and other selectors retain the active `D_80097680` table. Its existing
consumer `func_80060C98` converts 0x50-terminated GB strings to zero-terminated
strings through this decoder. The encoder searches the same table for the
output character and returns the corresponding GB byte index. This inverse
relationship establishes the names without assigning unverified languages
to individual modes.

Preserve the encoder's original byte-sized search index: if a value is
absent, the index wraps and the search never terminates. The nominal return
0 after the loop is unreachable in that case. The source marks this bug;
widening the index would change behavior. Both C switches use the existing
per-file rodata layout. Each is accepted through relocation-masked object
comparison and the sequential full-ROM gate, not direct link verification.
Unsigned-mode alternatives for the decoder conflict with its existing
signed-mode forward declaration; they are compile diagnostics, not useful
source-shape experiments. The accepted contract remains `u8 (u8, s32)`.

### Level hint and bounded binary search

The hinted level routine evaluates the same `func_80061B88` experience
curve as `Pokemon_LevelFromExp`. It clamps the incoming byte hint to 2..100
and maintains byte bounds initially 2 and 101. Each iteration compares
experience unsigned against the current and next level requirements.
It halves the appropriate interval, returns boundary levels 2/100 when
needed, and advances by one on exact equality with the next requirement.
The normal accepted C uses loop exits and one shared return. Early returns
change the branch joins despite preserving arithmetic. No signature repair,
dummy storage, padding or compiler patch is required.

### Deck entry reads

The deck reader dispatches on the high nibble of handle byte 1: 0x10 calls
`func_80053B38`, and 0x20 calls `func_8005D698` with the additional port byte
at 2. Both receive the signed cursor from 0x0A and destination pointer;
byte 3 selects the backend slot. A failed or unsupported read stops without
advancing the cursor. After success, increment the cursor and transferred
count, then advance the destination by the signed halfword at 0x08. The
byte at 0x05 limits the cursor. These observed roles take precedence over
the legacy `S1_DeckHandle` field names (whose `count` and `recordSize`
labels do not describe these uses); the new body does not propagate those
labels or change accepted neighboring definitions.

The post-decremented remaining-count condition and switch dispatch reproduce
the original 268-byte loop. Body-decrement and if-chain alternatives change
its control flow. Explicit integer-returning backend declarations match
this owner's consumed v0 results; unrelated translation units' void
declarations are not modified. Both this owner and the hinted search pass
direct link verification and full-ROM gates.

### Deck entry writes and temporary allocation

The paired writer dispatches to `func_80053F04`/`func_8005D778`, refreshes
the current entry count byte at 0x05 through `func_8005370C`/`func_8005CF20`,
and bounds the cursor by the signed capacity at 0x06. On success it advances
the cursor and transferred count, moves the input buffer by the signed
stride at 0x08, and sets dirty bit 0 at 0x04. Failed writes still perform
the original backend count refresh but do not advance or mark dirty.

The first eight cells reach the correct 324-byte instruction shape with
five remaining temporary-register differences (normalized 1.0, raw 0.9383).
Evaluating buffer advancement before setting the dirty bit reproduces the
original temporary demand order and closes the match. These updates are
independent: the stride read and dirty byte occupy distinct fields, and
the buffer is not accessed again until the next backend call. The accepted
statement order is cursor increment, transferred increment, buffer advance,
dirty update. No redundant carrier, dummy statement or forced register is
introduced. The winner passes direct link verification and the ROM gate.
