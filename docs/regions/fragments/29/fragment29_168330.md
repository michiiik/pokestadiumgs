### Selection scorer audit: reported zero excludes stack differences

The actual native candidate and stripped permuter base reproduce identical
function words; the GNU target reproduces the authoritative original ASM
span with only zero alignment bytes afterward. A bounded four-thread search
reports score 35 to zero in 1.8 seconds by wrapping the decrement/wrap arm
in `if (1)`. Independent native comparison rejects that exact proposal:
256 bytes, normalized 1.0 / raw 0.8906, still frame 0x28 instead of 0x20.
No source is installed. Eight scope/decrement cleanup variants also reject.

Cause: the wrapper did not request `--stack-diffs`. The permuter's objdump
normalizer replaces stack-frame immediates and stack-relative addresses when
that flag is absent. Source/target import calibration is necessary but does
not make that scoring mode exact. Enable stack differences for these frame
campaigns; never interpret the default zero as instruction-word identity.
A separately calibrated 45-second, four-thread search with `--stack-diffs`
starts at 85 and reaches 50, not zero. Native runner and full-ROM acceptance
remain authoritative. This changes local search configuration, not compiler
output or game source.

Eight natural switch-based alternatives (case order, do-loop versus label,
guard polarity) reject at 268 bytes, frame 0x30, best normalized 0.8507 /
raw 0.3284. Retain the calibrated search artifacts for a deeper frame-lifetime
investigation; do not repeat the scope/decrement or switch families, or adopt
the unconditional block on its normalized score.
