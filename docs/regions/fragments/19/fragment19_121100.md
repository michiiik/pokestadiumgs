## func_82300A78 is a shared-$at lui artifact, not a body-shape miss (tooling-blocked) (2026-09-07)

Ground truth is 15 instructions; the best hand candidate (`state-field:pointer-guard:early-return`, `s16 *state = &D_82305EB4; if (*state != 2) return; *state = 3; D_82305EC4 = 0; D_82305EC6 = 0; D_82305EC2 = 0; D_82305EC8 = 0;`) is 17 and its ONLY diff is the `bne` displacement (8 vs 10) -- the two extra instructions are two redundant `lui $at`. Two separate mechanism gaps were found and one of them is now fixed:

(2) FIXED: the bare `#pragma COALESCE_AT_LUI(f)` folds every maximal same-page run, which here collapses all five stores into one `lui` and produces 14 instructions -- one FEWER than ground truth. The pragma now takes an optional symbol list, `#pragma COALESCE_AT_LUI(func_82300A78, D_82305EC4, D_82305EC6, D_82305EC2)`, that both restricts folding to the named symbols and cuts the run at any op outside the list. (3) STILL BLOCKING -- the real reason this owner cannot land today: `coalesce_cc.py` reproduces an opted-in function by recompiling the source with `-S`, extracting that function block, folding it, and re-assembling the block on its own. ## func_82302258: the shape is a switch on a NON-foldable constant; 0.4156 -> 0.8431, one instruction short (2026-09-07)

requeue: the "constant-switch hypotheses optimized to 11-13 instructions versus the 50-instruction oracle" note above is now explained, and the family that reproduces the oracle's shape is found. Best is now `switch:counter-chain:per-group-vars-s32` at normalized 0.8431 / raw 0.1961, expected 200 bytes versus actual 204 -- exactly ONE instruction over, from a previous plateau of 0.4156 / 0.0909.

What the oracle actually is. Semantically the function only copies four halfwords: arg0[0x24] = D_82305D70[6], arg0[0x26] = [7], arg0[0x28] = [9], arg0[0x2A] = [8]. Everything else is 50 instructions of dead dispatch. The three dispatch groups are IDO switch lowering (compare chain first, case bodies out of line, `b` to a common merge -- NOT an if/else chain, which IDO lays out with `bne` and inline bodies). Each group is `switch (sel) { case 1: v = D[7]; break; case 2: v = D[9]; break; case 3: v = D[8]; break; }` with no default, so `v` carries over; group k's `sel` is k. The case constants 1/2/3 live in real registers ($a0/$a2/$a3), not in the assembler's `$at` immediate form, because three switches share them and IDO CSEs them; `beq $a0, $a0` is group 1's selector coalesced with the case-1 constant register. This is the only function in the whole ROM with a register-compared-against-itself branch (checked every .s).

Why every earlier candidate collapsed to 11-13 instructions. IDO -O2 folds `switch (x)` whenever x's reaching definition is a LITERAL assignment; it does not fold when the reaching definition is an arithmetic expression on a variable whose value is not derivable in the *pre-folding* CFG. Measured directly against the pinned IDO (disasm/tools/ido/macos/7.1/cc, -O2 -mips2 -G 0):
  - `s32 i = 1; switch (i)`               -> folded (12 instructions)
  - `s32 i = 0; i = i + 1; switch (i)`    -> folded
  - `s32 i = 0; switch (i); i = i + 1; switch (i)` -> the FIRST switch folds, the second does NOT
So a preceding switch on the same variable (which itself folds away and leaves no code) is what stops the next one folding: the fold decision is made against the original CFG, and is not re-run after an earlier switch is removed. `volatile` also stops the fold but forces a stack frame, which the oracle does not have (no `addiu $sp`), which is why every volatile candidate ran 232-312 bytes.

The best body (probe-stats label `switch:counter-chain:per-group-vars-s32`, declarations `extern u8 D_82305D70[];`):
    void func_82302258(u8 *arg0) {
        s32 a = 0, b = 1, c = 2;
        u16 v = D_82305D70[6];
        switch (a) { case 1: v = D_82305D70[7]; break; case 2: v = D_82305D70[9]; break; case 3: v = D_82305D70[8]; break; }
        *(u16 *)(arg0 + 0x24) = v;
        a = a + 1;  <same switch>  *(u16 *)(arg0 + 0x26) = v;
        b = b + 1;  <same switch>  *(u16 *)(arg0 + 0x28) = v;
        c = c + 1;  <same switch>  *(u16 *)(arg0 + 0x2A) = v;
    }
The first switch folds to nothing and supplies the unconditional `lbu $v0, 6($a1)` / `sh $v0, 0x24` prologue; the other three reproduce the oracle's three groups, including the out-of-line case bodies, the duplicated `li` constants in the branch delay slots and their fall-through copies, the `beql` third arm, and the dead trailing `lbu`.

The single remaining instruction. Opcode histogram, candidate versus oracle: +2 `move`, +1 `sh`, -1 `or`, -1 `nop`. The oracle keeps exactly six live values -- v($v0), an arg0 copy($v1), the constants 1/2/3($a0/$a2/$a3) and the D_82305D70 base($a1) -- i.e. IDO's first six allocatable registers, which is why it has to spill arg0 out of $a0 with `or $v1, $a0, $zero`. The candidate needs two extra selector temporaries, so it allocates eight registers, keeps arg0 in $a0 (no `or`), and one store gets duplicated into a delay slot. Group 3 already coalesces perfectly (`beq $t2,$t0` / `beq $t2,$t1` / `beq $t2,$t2`, no copy); groups 1 and 2 emit `move v0,t0` / `move v1,t1`.

Attempted and rejected for the last instruction (do not repeat): increment spelling (`++`, `+=`, `1 + a`, `|`, `/`, negative bases); selector width (u8/s16/u32); `v` as s32/u16; stores through a `u16 *p = (u16 *)arg0` local versus casts; a separate variable for the folding-breaker switch; an explicit `default: break;`; hoisting all the computed definitions into the entry block (folds); one variable incremented three times (leaves runtime `addiu $v0,$v0,1`, 0.6346); a goto chain with variable comparands (spills arg0 to the stack); an equivalent for-loop (IDO does not unroll it, even with `-Wo,-loopunroll,4/8`); IDO 5.3 (folds identically). A 600s 8-thread `tools/permute_candidate.py` pass from this body moved base score 1640 to 1055 without reaching zero.

Next action: this is now a register-allocation/coalescing tie on a correct shape, not a structural problem, and it does NOT need a .rodata subsegment or any other layout change. Seed the permuter from `switch:counter-chain:per-group-vars-s32` with a much larger budget, or find a spelling in which the group-1 and group-2 selectors coalesce into the case-constant registers the way group 3's already does (that alone removes the two `move`s, drops to six live values, and should pull the `or $v1, $a0, $zero` and the store scheduling into line).
