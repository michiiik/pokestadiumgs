# Main memory pool allocation and lifecycle management

## Binary-replacement audit

PR #1205 installed hardcoded instruction blobs for `func_800027F0` and
`main_pool_pop_state`. Its full-ROM comparison proved the patched binary,
not compilation of those C bodies. The earlier claim that this source was
fully decompiled is therefore unsupported. Track genuine matching status
independently of the presence of a C definition.

The submitted free body advances the left list head only when callbacks
are enabled, although original assembly always advances it. Its right-side
callback path also needs to reload the current right list head after a
callback. The submitted state-pop body incorrectly continues through older
checkpoints for a zero tag; original assembly stops after one checkpoint.

## main_pool_pop_state: accepted ordinary C

The checkpoint loop reads the pool's current state at each iteration,
snapshots its left and right boundaries, restores available space and the
previous state pointer, and stops immediately for a zero tag. For a nonzero
tag, it backs the checkpoint pointer up 16 bytes to inspect the allocation
header. It stops at a matching header tag or the end of the checkpoint
chain. It then invokes callbacks for discarded right and left allocations,
installs the saved boundaries, unlocks the queue and reports available space.

This source structure has an independently inspectable sibling in Stadium
1's `src/memory_main.c`. It is a structural hint, not the acceptance oracle.
The US Stadium 2 assembly and retail ROM remain authoritative. In particular,
reusing the checkpoint pointer for its allocation header reproduces the
address calculation that a separate header pointer folded away.

After 40 rejected ordinary candidates, the normal runner accepted the
296-byte body in `pop-state-reuse:direct-False:combined-False:typed-False`.
The frozen first accepted complete object has SHA256
`10ea911950c4e7a434f5dfd54b5a4ddd0a23f98022281e4aa672f0afafc5e9c1`.
It was preserved before any subsequent compilation. The original whole-file
object has SHA256
`e4d04c772ce35d97f26d1e835e801d6fc7fa550df7e566da0d50946014e70a60`.

The object probe's relocation-topology check differs because the C accesses
the checkpoint pointer through the pool base plus its field offset, whereas
the assembly names D_800CCDE0 directly. The sequential authoritative ROM
gate passes; this is not a claim that the preliminary relocation check
passed. No instruction replacement, forced register, dummy local, padding
workaround, volatile access or compiler-output patch is used by this body.

Independent links of the original and first accepted objects at retail
addresses reproduce all 14 function extents and all 1920 text bytes,
including padding, at ROM 0x3280. Fresh final-source and twenty-blank
complete-TU fingerprints also equal the frozen accepted object. The final
native full-ROM comparison passes with MD5
`1561c75d11cedf356a8ddb1a4a5f9d5d`; all 76 native tool tests and all 427
host-syntax translation-unit checks pass. This verifies the state-pop
correction, not genuine C completion of the other binary-replaced owners.

## func_800027F0: accepted ordinary C

The free operation derives the requested allocation header without changing
the incoming address, then retains that endpoint through callback traversal.
It advances the left list head even when callbacks are disabled. On the
right, a callback can change the live head, so the function reloads it before
advancing and accounting for the reclaimed block. The final available-space
return and caller interfaces are unchanged.

After 72 ordinary attempts, an eight-candidate derived-endpoint batch
accepted `free-derived-endpoint:unsigned-True:branch-False:block-first-False`.
Unsigned 32-bit header arithmetic separates the initial short-lived address
from the saved endpoint. It reproduces the original 284-byte body and
40-byte frame, including the initial v1 address and s2 endpoint. The object
probe is link-verified and the authoritative combined full-ROM gate passes.
The earlier parameter-modifying spelling kept the initial address in a0;
its normalized 1.0 result was not accepted. The earlier register-tie warning
and flat conservative search did not prove a source match impossible.

The complete first accepted object was frozen before any further
compilation, SHA256
`6ff523862cbf40d656b25f173d7b0c178e781acfbe941ecd03c0a32f27949f32`.
A verified readability cleanup compares byte addresses within the pool
arena instead of casting a header pointer back to an integer. Fresh final
source and twenty-blank whole-TU controls preserve the frozen accepted game
fingerprint: all allocatable bytes/layouts, symbols and relocations.

Independent links of the original, state-pop acceptance and free acceptance
objects reproduce all 14 function extents and all 1920 text bytes at ROM
0x3280, including padding. The final native ROM comparison passes with MD5
`1561c75d11cedf356a8ddb1a4a5f9d5d`; all 427 host-syntax C checks and 76
native tool tests pass. This source no longer contains either complete-
function binary replacement. No compiler change, forced register, dummy
local, artificial home, padding workaround or coverage edit is involved.

The other audited replacements in 66DF0, 4CC20 and 73C80 remain separate
unresolved work; this file's verification does not establish their C matches.
