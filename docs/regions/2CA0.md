# Segment memory-map command emission

## Historical source-shape investigation, 2026-10-20

The pre-correction C facade used a word rewrite at function offset `0x4C` to change
the first command store from `$s1` to `$s3`, plus an empty conditional on the
advanced display-list pointer. Neither establishes a genuine source match.
The private native source restores the original `GLOBAL_ASM` function and
removes that rewrite before probing. This assembly baseline passes the normal
full-ROM comparison. Its successful callback freezes the complete `2CA0`,
`585D0`, `615D0`, `4C2E0` and fragment-38 objects and externally hashes them
before returning; the receipt and all five hashes are rechecked before probes.

The assembly emits sixteen segment commands from the eight-byte entries
between `D_800CC5B0` and `D_800CC630`. Each command has header `0xDB060000`
with the segment index multiplied by four, and a physical base obtained
through `osVirtualToPhysical`. The output pointer advances once per command
and is stored through the incoming pointer after the loop. Stadium 1's
`Memmap_SetSegments` is a structural witness for the SDK `gSPSegment` macro,
not target-byte proof.

Four eight-candidate batches pass known/context/twenty-leading-blank full
original-object controls. All 32 candidates reject; no C body is installed.
Private artifacts use these prefixes:

- `scratch/native-segment-list-packet`: inline SDK result and packet-pointer
  advance, signed/unsigned counters and for/do loops. Best 152 bytes, raw
  0.8421; the original is 152 bytes with a 48-byte frame.
- `scratch/native-segment-list-value-flow`: actual base/result temporaries,
  packet-pointer advance position, declaration initialization and result-store
  position. Best raw 0.8947, with the original size and frame.
- `scratch/native-segment-list-index-macro`: actual SDK segment index rather
  than a divided byte-offset counter, macro/manual expression, endpoint local
  and loop form. Cell 2 reaches raw 0.9211 at the original size and frame.
- `scratch/native-segment-list-endpoint-carriers`: combine an explicitly
  initialized endpoint with real result carriers and delayed command store.
  Best raw 0.8158; explicit endpoint ownership changes allocation and does
  not solve the retained residual.

Requeue the macro batch's cell 2 and the value-flow batch's cell 1 as distinct
parents. The best macro parent has matching allocation but schedules the
start/end-address low halves differently (first differing word offset `0x30`)
and writes the second command word before the final loop increment/branch,
where the original puts that store in the branch delay slot. Investigate
natural statement/macro expansion and scheduling topology; do not repeat the
endpoint-local grid, retain the empty conditional, force registers, or patch
the command store. These requeues are superseded by the accepted fixed-count
source below.

## Accepted: `Memmap_SetSegments`, 2026-10-20

`Memmap_SetSegments` (`func_80002178`, 152 bytes) uses the sixteen-entry
segment count directly: a `for` loop indexes the actual eight-byte map
entries and emits `gSPSegment(gdl++, segment, osVirtualToPhysical(base))`.
The compiler naturally strength-reduces the array accesses and produces the
original command pointer, loop allocation and branch-delay store. No empty
conditional, dummy local, manual padding or instruction rewrite remains.
The descriptive name is supported by those sixteen segment commands and
Stadium 1's equivalent operation; the old address name retains a linker alias.

The first new batch moves real pointer/index postincrements inside the SDK
macro; all eight variants retain the previous scheduling residual. The next
eight-candidate batch uses the genuine fixed count. Its indexed unsigned
`for` loop is accepted by the normal runner and full-ROM sequential gate;
remaining variants are skipped, not probed again after acceptance.

The array endpoint is represented as `D_800CC5B0 + 128` rather than the
adjacent `D_800CC630` label, so unlinked relocation fields differ. That is
reported as `relocation_masked: true`, `link_verified: false` and
`relocation_drift`, not presented as raw object identity. The normal linked
ROM gate proves the actual result. Independent retail-address links cover
all thirteen function extents and 1,504 complete text bytes for the original,
accepted and named module objects.

The acceptance and final named gates freeze five complete support objects
inside each successful callback, reread receipts and externally hash every
snapshot before returning and before further compilation. All collateral
fingerprints remain unchanged. Canonical/descriptive names, native/public
compiler paths and twenty-leading-blank controls reproduce their respective
accepted whole-module fingerprints and retail text. Accepted-attempt
provenance, all-source host syntax, all 76 native tests and the final normal
ROM checksum `1561c75d11cedf356a8ddb1a4a5f9d5d` pass. No `GLOBAL_ASM` or
`REWRITE_FUNCTION` directive remains in `src/2CA0.c`.
